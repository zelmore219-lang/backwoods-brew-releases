# Backwoods Employees 0.4.2

This Driver companion adds managed Driver account access, shared Main/Driver/Employee timecards, administrator review and corrections, guarded payroll inputs, and the trusted service for approved, newly signed Driver invoice revisions. It retains the Employee icon, existing onboarding workflow, username/password authentication, Firebase project and Windows data folder.

Install Backwoods-Employees-Setup-0.4.2.exe using the same Windows account as before. Save work and close the app first. Employee records and the encrypted document key remain in place. Existing Employee updaters receive this version through App updates. An installation without the updater needs this setup once.

On the Windows PC containing the actual Employee records, open **Owner service → Connect or manage owner service**, connect the Google owner of the existing Backwoods Firebase project, review the existing HR owner/Main account association, and start the service. Keep that PC awake and online. Link each Driver's existing Firebase UID to their real HR record, grant the appropriate access, and review the actual company, division, job and workweek before approving payroll. Invoice corrections use the existing company Accounting ledger. No employees, pay rates, retail locations or company books are created automatically. Firebase stays on its free plan; owner credentials remain private on the owner PC.

Android: Backwoods-Employees-0.4.2.apk updates Employee 0.4.1 using the retained signing identity and also supports a new installation. It cannot update the legacy 0.3.0-full signing identity. Keep that older app and its records; do not uninstall it to bypass Android's signature protection. The native updater checks the package, signing identity, version, device compatibility, size and SHA-256 before the Android installation confirmation.

Verification: 90 Python tests (16 emulator/browser-only cases skipped in that unit run), separate Auth/Firestore integration tests covering shared timecards and protected invoice revisions, the real Driver/admin approval and new-signature browser workflow, and 12 updater tests passed. The Windows package passed upgrade from 0.3.1, restart and reinstall while preserving the employee record and DPAPI document key, isolated owner-window controls and bundled administration SDK loading. Android policy/install-handoff tests and the packaged Python engine passed on an Android emulator. The owner's live Windows service, actual company device and physical printer still require device acceptance. Separate onboarding document drafting remains deferred. Production app work remains separate. Main, Vendor and Accounting updater feeds are preserved.
